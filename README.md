# distillarium-app

**GitHub:** <https://github.com/doc9830/distillarium-app>

Android-приложение «Дистиллярий»: вики, справочник, калькуляторы, партии и
рецепты. Офлайн-первый: весь контент лежит на устройстве, сеть нужна только
для обновления контента и приложения.

**Лицензия:** source available, см. [`LICENSE`](LICENSE). Код открытым
исходным не является.

## Структура

```
app/                      Android-приложение: Compose, «Главная», «Партии», «Обновления»;
                          «Знания» и «Расчёты» открываются плитками с главного экрана
  src/main/java/.../knowledge/  разбор статей, дерево, поиск, загрузка пакета
  src/main/java/.../batches/    user.db, партии, шаги, напоминания
  src/main/java/.../recipes/    шаблоны рецептов из пакета
  src/main/java/.../appupdate/ проверка app-manifest.json, загрузка и установка APK
  src/main/java/.../ui/         экраны, Markdown-рендер, навигация
  src/main/assets/        content-pack.zip и manifest.json (встроенный пакет)
core/content/             Kotlin/JVM: манифест, проверка, ZIP, подмена, откат
core/data/                не используется: user.db работает на SQLiteOpenHelper в app/batches
tools/sync-content.mjs    копирование собранного пакета в assets
tools/app-release-manifest.mjs  app-manifest.json для GitHub Releases
.github/workflows/app.yml       тесты, lint, APK
.github/workflows/release.yml   релиз APK по тегу app-v* и обновление app-latest
```

`core/content` не знает об Android и UI: его тесты идут на JVM без эмулятора.
`app` — тонкая обёртка: assets, OkHttp, WorkManager, Compose. `core/data`
намеренно пуст: для одной пользовательской базы хватает `SQLiteOpenHelper`,
Room и FTS5 не понадобились.

## Стек

| Слой | Решение |
| --- | --- |
| Язык и UI | Kotlin 2.2.20 + Jetpack Compose, Material 3 |
| Markdown | CommonMark 0.30.1 + GFM-таблицы, свой Compose-рендер |
| Поиск M1 | индекс в памяти, синонимы и лёгкое усечение словоформ |
| Обновления | WorkManager + OkHttp |
| Пользовательские данные | SQLite (`user.db`) через `SQLiteOpenHelper`, без Room |
| JSON | kotlinx.serialization |
| minSdk / targetSdk / compileSdk | 26 / 36 / 36 |
| Gradle / AGP | 8.13 / 8.13.0 |

Версии зафиксированы в `gradle/libs.versions.toml`. Compose BOM и AndroidX
взяты из стабильной ветки, современной Kotlin 2.2.20: обновлять их нужно
вместе с Kotlin, а не по одному. Lint предупреждает о новых версиях — это
ожидаемо и не ошибка сборки.

Нужны JDK 21 и Android SDK с platform 36 / build-tools 36.0.0.

```bash

export ANDROID_HOME="$HOME/Android/Sdk"

```

Полная локальная проверка:

```bash
./gradlew --no-daemon :core:content:test :app:testDebugUnitTest lintDebug assembleDebug
```

Проверки M0/M1 на реальном устройстве **2409FPCC4G, HyperOS, Android 16 (API 36)**:

- debug APK устанавливается и запускается (холодный старт ≈1.5–2 с);
- первый запуск ставит встроенный пакет: `source=embedded`, 2 статьи;
- после перезапуска `installedAt` не меняется, повторной установки нет;
- на момент M1 `databases/` был пуст — `user.db` ещё не создавался;
- WorkManager ставит периодическую работу на 24 ч с `UNMETERED`;
- фоновая проверка при недоступном сервере не показывает ошибку на экране.

M2–M3 проверены на устройстве smoke-тестом: открываются таблицы, статьи,
партия с шагами/замерами/журналом и калькуляторы; напоминание доставлено
через `BatchReminderWorker`. M4 проверен тестами, lint и сборкой, но ещё
не принят вручную.

## Контент в APK

Пакет лежит в `app/src/main/assets/`. Он собран из `distillarium-content`
и скопирован туда скриптом:

```bash
cd ../distillarium-content
node tools/build-content.mjs

cd ../distillarium-app
node tools/sync-content.mjs          # копирует и проверяет размеры/sha256
node tools/sync-content.mjs --check  # только проверка, без копирования
```

`EmbeddedContentTest` открывает именно эти assets, устанавливает пакет в
temp-каталог и проверяет 2 статьи, 1 ссылку, 0 редиректов, 19 файлов и
7 рецептов. Сейчас в APK встроен пакет `2026.10.12`
(`minAppVersion 1.0.4`). `EmbeddedWikiTest` дополнительно проверяет, что статья,
размещённая в двух разделах, даёт два листа с разными ключами, а каждый шаг
рецепта ведёт на существующую статью. Если контент и валидатор приложения
разойдутся, тест упадёт до релиза.

## Вики M1

- `WikiLoader` читает активный пакет из `files/content/current`, а не из APK:
  после обновления статьи сразу новые.
- `ArticleParser` разбирает frontmatter без YAML-библиотеки: строки, массивы,
  кавычки и многострочный `short` из конвейера контента.
- `ArticleBodyParser` вынимает `::: tabs` / `== Название ==`; остальное тело
  остаётся Markdown.
- `MarkdownContent` даёт абзацам отдельный нижний отступ и увеличенный
  межстрочный интервал, а заголовки и списки — собственные блоки, поэтому
  статья в приложении читается так же, как в предпросмотре редактора.
- `WikiTree` строит дерево из `tree.json`: разделы, порядок и размещение статей
  не зависят от id. Конфигурация авторитетна: пустые разделы сохраняются,
  неразмещённые статьи попадают в «Без раздела». Fallback по путям id
  (`raw/...`, `processes/...`) используется только если `tree.json` нет или он
  битый. Категории статей больше не образуют отдельную навигацию, а теги —
  только явно указанные автором `tags`.
- `WikiLibrary.resolve` понимает id и старые адреса `/articles/...` из
  `redirects.json`; `backlinks` собираются по `[[ссылкам]]` при загрузке.
- `KnowledgeScreen` показывает на корне плитки разделов, а внутри раздела —
  карточки подразделов и компактный список статей. Пустые разделы остаются в
  `tree.json` и редакторе, но в приложении скрыты. Навигация идёт по пути
  разделов с кнопкой «Назад» и хлебными крошками; системная кнопка «Назад»
  ведёт по тому же пути. Теги вынесены в компактный горизонтальный фильтр:
  отдельного экрана категорий нет, drag-and-drop структура из редактора и есть
  навигация «Знаний».
- `SearchEngine` ищет по заголовку, подзаголовкам, короткому описанию и тексту,
  понимает «сивушные» → хвосты и «сахаромер» → ареометр.
- `DistillariumRoot` держит нижнюю навигацию `Сейчас | Партии | Обновления`
  и стек маршрутов; «Знания» и «Расчёты» открываются плитками на «Главной».
  Читалка: крошки, оглавление в шторке, A−/A+, вкладки
  оборудования, таблицы с горизонтальным скроллом, «Сюда ссылаются», «Наверх»,
  «Поделиться». Статья из шага партии открывается поверх партии, «Назад»
  возвращает к шагу.
- `EXTRA_ARTICLE_ID` / `EXTRA_ARTICLE_HEADING` в `MainActivity` позволяют
  открыть статью и раздел по intent — используется для проверки на устройстве.

## Справочник и калькуляторы M2

- `ReferenceLoader` читает `reference/*.json` из активного пакета; таблица
  открывается из статьи по `ref:` и умеет вести обратно в статью.
- `Calculators` — 26 калькуляторов в 6 группах. Формулы вынесены в чистый Kotlin
  и покрыты тестами с конкретными числами.
- `calculators.json` — каталог всех 26 калькуляторов (id, название, группа,
  источник). Из него редактор строит список для вставки ссылок, поэтому в нём
  видны все формулы. Ссылки `calc:` из статей и поле `calc` таблиц разрешаются
  в эти id и проверяются при установке пакета и в JVM-тестах.

## Партии и рецепты M3

- **Рецепт — шаблон, партия — экземпляр.** `RecipeLoader` читает
  `recipes/*.json`; при создании партии название, тип, объём и шаги
  копируются в `user.db`. Последующее обновление контента партию не меняет.
- `UserDatabase` — отдельный `user.db`: `batches`, `batch_steps`,
  `measurements`, `journal`, `calcs_saved`, `favorites`. Включены внешние
  ключи, схема версионируется.
- Срок шага считается от предыдущего шага (`afterDays`), поэтому перенос
  даты постановки не ломает план. Просроченные шаги подсвечиваются.
- Замеры хранят плотность, температуру, заметку и расчётную крепость; при
  двух и более замерах рисуется график плотности.
- «Повторить партию» копирует шаги с новыми датами, но не переносит замеры
  и журнал исходной партии.
- Напоминания — `BatchReminderWorker` на `WorkManager`, раз в сутки, без сети. Worker берёт
  ближайшие незакрытые шаги из `user.db` и показывает локальные уведомления
  (не более 5 за запуск). Разрешение `POST_NOTIFICATIONS` запрашивается на
  экране «Сейчас»; если уведомления выключены, там же есть вход в настройки.

## Адрес обновлений

По умолчанию:

```
https://github.com/doc9830/distillarium-content/releases/download/content-latest/manifest.json
```

Репозиторий контента **публичный**, поэтому приложение скачивает релизные файлы
по прямым ссылкам без авторизации. Проверено 19.10.2026: `content-latest`
отдаёт `manifest.json` и `content-pack.zip`; sha256 архива совпадает с
`packSha256`. При необходимости адрес можно переопределить без правки кода:

```bash
./gradlew -Pdistillarium.contentManifestUrl=https://example.org/content/manifest.json assembleDebug
```

или строкой в `~/.gradle/gradle.properties`. Разрешён только HTTPS. Архив
берётся из соседнего asset: `…/content-pack.zip` рядом с `manifest.json`.
Релиз `content-latest` должен содержать оба файла — так его собирает
workflow репозитория контента.

## Обновление приложения

Версия приложения хранится в `app/version.properties` в виде `versionName=1.0.6`.
`versionCode` не задаётся вручную: Gradle, Kotlin-парсер и
`tools/app-release-manifest.mjs` считают его одинаково —

```
versionCode = major * 1_000_000 + minor * 1_000 + patch
```

По умолчанию приложение проверяет

```
https://github.com/doc9830/distillarium-app/releases/download/app-latest/app-manifest.json
```

`app-latest` — изменяемый релиз только с `app-manifest.json`; сам APK лежит в
неизменяемом релизе `app-v<версия>`, поэтому ссылка и sha256 в манифесте не
меняются. Проверка идёт при запуске и по кнопке на вкладке «Обновления».
Если версия в манифесте новее установленной, на «Сейчас» появляется баннер,
а на «Обновлениях» — карточка с версией, размером и заметками.

Загрузка и установка:

1. APK скачивается в `files/app-update/` с проверкой размера и sha256 по мере
   чтения; несовпадение удаляет файл.
2. Перед установкой проверяются package name, `versionCode` и сертификат
   подписи: обновление должно быть подписано тем же ключом, что и установленное
   приложение.
3. Открывается штатный установщик Android. Приложение не устанавливает APK
   молча: нужны разрешение `REQUEST_INSTALL_PACKAGES` и «Установка неизвестных
   приложений» для «Дистиллярия». После возврата из настроек экран повторяет
   установку.
4. `user.db`, партии, замеры и настройки не затрагиваются.

Проверить вкладку на устройстве можно без ручных нажатий:

```bash
adb shell am start -n ru.distillarium/.MainActivity \
  --es ru.distillarium.extra.START_TAB Updates
```

### Релиз

Релизная подпись — отдельный ключ, не debug:

```bash
keytool -genkeypair -v -keystore ~/.android/distillarium-release.jks \
  -alias distillarium -keyalg RSA -keysize 4096 -validity 10000
```

`keystore.properties` в корне репозитория (в git не попадает):

```properties
storeFile=/home/user/.android/distillarium-release.jks
storePassword=…
keyAlias=distillarium
keyPassword=…
```

Локальная сборка: `./gradlew assembleRelease`. APK будет подписан, если
`keystore.properties` существует; без него Gradle соберёт неподписанный APK.

Публикация:

1. Поднять `versionName` в `app/version.properties` (например, `1.0.1`) и
   закоммитить.
2. Поставить тег `app-v1.0.1` и запушить его:
   `git tag app-v1.0.1 && git push origin app-v1.0.1`.
3. Workflow `.github/workflows/release.yml` проверит совпадение тега и версии,
   прогонит тесты и lint, соберёт и проверит подпись APK, создаст релиз
   `app-v1.0.1` с APK и `app-manifest.json`, затем обновит `app-latest`.

Секреты репозитория: `APP_KEYSTORE_BASE64` (base64 от `.jks`),
`APP_KEYSTORE_PASSWORD`, `APP_KEY_ALIAS`, `APP_KEY_PASSWORD`.

## Что происходит при запуске и обновлении

1. `MainActivity` создаёт `DistillariumRoot`; `KnowledgeViewModel` просит
   `ContentRepository.currentDirectory()`, а `UpdatesViewModel` —
   `ensureInstalled()`.
2. Если `files/content/current` цел — используется он. Если нет — previous,
   затем встроенный пакет. Сеть для этого не нужна. Вики читается из
   `current`, поэтому после обновления не нужен перезапуск.
3. Обновление: GET манифеста с `If-None-Match` → сравнение версий как чисел →
   проверка `schemaVersion` и `minAppVersion` → скачивание в
   `files/content/download.tmp` → проверка размера и sha256 всего архива →
   распаковка в `update.tmp` с защитой от zip-slip и лимитом объёма →
   проверка каждого файла, ссылок, редиректов, медиа и индекса поиска →
   `current → previous`, `update.tmp → current`, запись `installed.json`.
4. Любая ошибка до подмены оставляет `current` нетронутым. После подмены
   сбой записи состояния возвращает previous на место.
5. Откат: `current → broken.tmp`, `previous → current`; бывший current
   становится previous, поэтому откат обратим.

Раскладка на устройстве:

```
files/
  content/
    current/            активный пакет (только чтение)
    previous/           один предыдущий пакет
    update.tmp/         временная распаковка, удаляется
    broken.tmp/         только на время отката
    previous.json       состояние previous для отката
    etag.txt            ETag манифеста (не пользовательские данные)
    download.tmp        временный архив, удаляется
  installed.json        {contentVersion, schemaVersion, installedAt, packSha256, source}
databases/
  user.db               НЕ ТРОГАЕТСЯ конвейером контента
```

`source` — расширение формата (`embedded`, `download`, `rollback`,
`recovered`), нужно только экрану «Обновления».

## Гарантии и тесты

1. Обновление не меняет `user.db`: тест создаёт файл в `databases/`,
   запоминает sha256, ставит новый пакет и сверяет хеш.
2. Битый архив, неверный sha256, zip-slip, битая ссылка, слишком новая схема
   и слишком новый `minAppVersion` не устанавливаются; `current` остаётся.
3. Откат возвращает previous, а прежний current оставляет доступным.
4. Обрыв процесса после `current → previous` и посреди отката
   восстанавливается при следующем запуске (`previous` или `broken.tmp`).
5. Офлайн: после первой установки `ensureInstalled()` не требует assets и
   сети; тест передаёт заведомо отсутствующие файлы.

Тесты: `core/content/src/test` (установщик, загрузчик, версии) и
`app/src/test` (реальный встроенный пакет).

## Ограничения текущей сборки

- Настроек пока нет, «Обновления» — отдельная вкладка; позже переедут в настройки.
- Поиск работает по индексу в памяти. `search/index.json` проверяется
  конвейером и читается напрямую, в SQLite не переносится.
- Markdown-картинки пока показываются заглушкой: медиа в пакете ещё нет.
- Партии удаляются безвозвратно (жёсткое удаление вместе с шагами, замерами,
  журналом и сохранёнными расчётами); архива и корзины нет. Экспорт и фото
  в журнале — не делались.
- Сохранённые расчёты и избранное работают; пользовательские рецепты
  (не из контента) пока не создаются.
- `user.db` версии 2: миграция добавляет `note` в `calcs_saved` и таблицу
  `calc_favorites`, данные версии 1 сохраняются.
- Напоминания: одна периодическая работа раз в сутки (по умолчанию 9:00),
  не больше пяти самых ранних шагов за запуск; точное время доставки зависит
  от Doze/WorkManager. Доставка проверена на устройстве через
  `BatchReminderWorker`; уведомление не открывает партию по нажатию.
- WorkManager проверяет обновления контента раз в сутки по unmetered-сети;
  обновление APK проверяется при запуске и вручную, уведомлений об этом пока нет.
- M4 на реальном устройстве ещё не принят вручную: проверены сборка, тесты
  и lint, но не сценарий «сохранить расчёт → открыть из партии».
- Лицензия на контент ещё не выбрана (см. `docs/10` в корне проекта).
- Репозиторий контента остаётся приватным: OTA контента не работает без
  публичного адреса. OTA приложения использует публичный `distillarium-app`.

## Что нельзя нарушать

1. Обновление контента пишет **только** в `files/content/` и
   `files/installed.json`. В `databases/user.db` — никогда.
2. Любая ошибка скачивания, распаковки или проверки оставляет текущий пакет
   нетронутым. Приложение продолжает работать офлайн.
3. Контент не выполняет код: только Markdown и JSON.
4. Пакет новее `schemaVersion` приложения не ставится.
5. `minAppVersion` больше версии приложения — пакет не ставится, показывается
   предложение обновить приложение.
